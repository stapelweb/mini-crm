# Решения и допущения

Где ТЗ допускает несколько прочтений — что выбрано и почему.

## Решения

1. **Смена статуса — только через функцию базы `change_task_status`.**
   Прямой `UPDATE` поля статуса запрещён триггером всем, включая постановщика.
   Так проверка перехода и запись в историю происходят одним действием, и их
   нельзя разделить или обойти.

2. **История пишется триггером, а не приложением.** Политик на запись, правку и
   удаление у таблицы истории нет вовсе, права отозваны явно. Подделать запись
   через API нельзя даже постановщику.

3. **Профиль пользователя заводится автоматически** при создании учётной записи
   (триггер на `auth.users`). Роль по умолчанию — исполнитель; постановщика
   назначает администратор.

4. **Список людей видят все вошедшие.** Иначе в истории и в поле «исполнитель»
   вместо имён были бы идентификаторы. Из профиля видно только имя и роль.

5. **Задача может существовать без исполнителя.** Постановщик заводит её, пока
   не решил, кому отдать. Взять такую задачу в работу нельзя, пока он не
   назначит человека, — это следует из правил переходов.

6. **Исполнителя назначает и меняет только постановщик.** В ТЗ прямо не сказано,
   кто это делает после создания; отдать это исполнителю означало бы дать ему
   возможность забрать чужую задачу.

7. **Выкладка на GitHub Pages**, сборка в GitHub Actions. Адрес проекта и
   публикуемый ключ приходят из переменных репозитория. Ключ `service_role` в
   проекте не используется вовсе.

8. **Интерфейс намеренно простой**: дизайн не оценивается, а время лучше
   потратить на права и переходы.

## Допущения

* Ролей ровно две, у пользователя она одна. Постановщик не может быть
  исполнителем своей же задачи.
* Удаление объекта удаляет его задачи вместе с историей — это каскад в базе.
  Если нужно иначе (архив вместо удаления), это отдельное решение.
* Комментарий обязателен только при возврате на доработку. На остальных
  переходах он разрешён, но не требуется.
* Почта и уведомления не делались — в ТЗ их нет.
* Демонстрационные учётные записи заведены вручную, открытая регистрация
  выключена, подтверждение почты для них не требуется.

## Что не успел

* Нет страницы «все мои объекты» для постановщика с фильтром по статусу —
  список объектов плоский, фильтрации и поиска нет.
* Нет правки и удаления задач и объектов из интерфейса: права в базе на это
  у постановщика есть, экранов не сделал.
* Нет автоматических тестов интерфейса. Проверка прав покрыта скриптом
  `scripts/security-check.mjs`, интерфейс проверялся руками.
