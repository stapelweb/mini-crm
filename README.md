# Мини-CRM «Объекты и задачи»

Небольшая CRM для строительной компании: руководитель ставит задачи по объектам,
исполнители берут их в работу и сдают на проверку.

Стек: React 19 + TypeScript + Vite, Supabase (Postgres, Auth, RLS).

## Что где лежит

```
supabase/migrations/   миграции базы, применяются по порядку
  0001_schema.sql      таблицы, типы, профиль пользователя
  0002_transitions.sql разрешённые переходы статусов и история
  0003_rls.sql         права доступа (RLS) и отзыв лишних прав
  0004_seed.sql        демонстрационные данные
scripts/
  security-check.mjs   проверка прав в обход интерфейса
src/
  lib/                 клиент Supabase, типы, таблица переходов
  pages/               вход, объекты, карточка объекта, карточка задачи, мои задачи
```

## Как запустить у себя

```bash
npm install
cp .env.example .env     # вписать URL проекта и publishable-ключ
npm run dev
```

Базу поднять с нуля: выполнить файлы из `supabase/migrations` по порядку в
SQL-редакторе Supabase. Пользователей завести вручную в Authentication → Users
(открытая регистрация выключена), затем выполнить `0004_seed.sql`.

Проверка прав:

```bash
node scripts/security-check.mjs
```

Скрипт ходит в Supabase напрямую, тем же публичным ключом, что лежит в браузере,
и проверяет 14 утверждений — что исполнитель не видит чужого, что запрещённый
переход не проходит и что историю нельзя подделать или стереть.

## Как устроен доступ

Права закрыты в базе, а не в интерфейсе. Интерфейс только прячет кнопки,
которые всё равно не сработают.

* **Чтение.** Постановщик видит всё. Исполнитель видит свои задачи и те объекты,
  где у него есть хотя бы одна задача. Это политики RLS, они действуют при любом
  обращении к API.
* **Смена статуса.** Прямой `UPDATE` статуса запрещён всем, включая постановщика:
  его останавливает триггер. Единственная дверь — функция `change_task_status`,
  которая сама проверяет роль, исполнителя, допустимость перехода и обязательный
  комментарий при возврате на доработку.
* **История.** Пишется триггером. Политик на запись, правку и удаление нет вовсе,
  и права отозваны явно — подделать или стереть историю через API нельзя.
* **Регистрация.** Отключена. Учётные записи заводит администратор.
* **Ключи.** В браузер уходит только publishable-ключ, он на то и рассчитан.
  Ключ `service_role` в проекте не используется и в репозиторий не попадает;
  `.env` в `.gitignore`.
